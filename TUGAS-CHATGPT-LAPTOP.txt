TUGAS 1 — PASANG KUNCI GOOGLE PLAY DI CLOUDFLARE (PALING PENTING)
------------------------------------------------------------------------
Masalah sekarang: secret GOOGLE_PLAY_SERVICE_ACCOUNT_JSON di worker berisi EMAIL
service account (59 karakter), bukan isi file JSON. Akibatnya pembeli lewat Google Play
bayar tapi paketnya TIDAK aktif otomatis.

Cek status sekarang (aman, tidak membuka rahasia):
  https://berstock-bot.hendrypangg12.workers.dev/api/google-play/health
Sekarang hasilnya: "length":59, "parses":false  -> SALAH.

Langkah:
a. Buka https://console.cloud.google.com -> pilih project ber-uang-735b3
   -> IAM & Admin -> Service Accounts.
b. Klik service account: beruang-play-billing@ber-uang-735b3.iam.gserviceaccount.com
   -> tab Keys -> Add key -> Create new key -> JSON -> Create.
   File .json akan terunduh.
c. Buka file itu dengan Notepad. Isinya diawali {"type": "service_account", ...
   dan panjangnya sekitar 2.300 karakter. Salin SEMUA isinya (Ctrl+A, Ctrl+C).
d. Buka https://dash.cloudflare.com, login dengan hendrypangg12@icloud.com
   (pastikan Account ID 55dcdad9...).
   Workers & Pages -> berstock-bot -> Settings -> Variables and Secrets.
e. Edit secret GOOGLE_PLAY_SERVICE_ACCOUNT_JSON (Type harus "Secret"),
   hapus isi lama, tempel isi JSON lengkap -> Save/Deploy.
f. Hapus file .json dari folder Downloads setelah berhasil (jangan disimpan sembarangan).

Cek berhasil: buka lagi /api/google-play/health. Harus:
  "present":true, "parses":true, "hasClientEmail":true, "hasPrivateKey":true, "projectMatches":true
Kalau "projectMatches":false, kunci dibuat dari project yang salah.

Pastikan juga di Play Console -> Users and permissions, email service account di atas
punya izin minimal "View financial data" dan "Manage orders and subscriptions".

TUGAS 2 — BUILD ANDROID 1.4.1 (versionCode 7)
------------------------------------------------------------------------
Build 1.4.0 (versionCode 6) yang ada di Internal Testing punya BUG: layar paket
(paywall) tidak tampil. Build 1.4.1 memperbaikinya, plus fitur baru:
rating Play Store dalam app, panduan user baru, hitungan penjualan anonim.
versionCode 7 / versionName 1.4.1 SUDAH diset di mobile/android/app/build.gradle.

Langkah (sesuaikan untuk Windows PowerShell / Mac):
  git fetch origin
  git checkout claude/financial-tracking-app-QUmrz
  git pull origin claude/financial-tracking-app-QUmrz
  cd mobile
  pnpm install

  # WAJIB mode production saat staging (menandai build toko):
  # PowerShell:  $env:BERUANG_BUILD_KIND="production"
  # Mac/Linux:   export BERUANG_BUILD_KIND=production
  pnpm sync          # = stage web + cap sync android (memasang plugin rating baru)

  # Variabel penandatanganan (pakai keystore upload yang sama dengan build 1.4.0):
  #   BERUANG_UPLOAD_STORE_FILE     = path file keystore
  #   BERUANG_UPLOAD_STORE_PASSWORD = password keystore
  #   BERUANG_UPLOAD_KEY_ALIAS      = alias kunci
  #   BERUANG_UPLOAD_KEY_PASSWORD   = password kunci
  cd android
  ./gradlew bundleRelease -PberuangProduction=true      (Windows: .\gradlew.bat ...)

Hasil: mobile/android/app/build/outputs/bundle/release/app-release.aab
Cek: package id.berstock.beruang, versionCode 7, versionName 1.4.1.

Tes sebelum build (opsional tapi disarankan):
  cd mobile && node --test test/native.test.mjs      -> semua pass
  cd bot && npm install && npm test                  -> semua pass

Catatan: "pnpm sync" mengubah mobile/android/capacitor.settings.gradle sesuai laptop.
Itu normal. Tidak perlu di-commit.

TUGAS 3 — PLAY CONSOLE: DATA SAFETY (sebelum kirim 1.4.1)
------------------------------------------------------------------------
Build 1.4.1 mengirim hitungan pemakaian anonim ke server BerUang (tanpa email/nama/isi
transaksi). Kebijakan privasi sudah diperbarui: https://berstock.id/privacy.html
Di Play Console -> App content -> Data safety -> Edit:
- Tambah "App activity" -> "App interactions":
  Collected = Ya. Shared = Tidak. Tujuan = Analytics.
  "Linked to user's identity" = pilih YA (pilihan paling aman: hitungan dikirim saat user
  login, walau server hanya menyimpan angka total + penanda acak hasil hash).
  "Processed ephemerally" = Tidak. "Required/optional" = Required.
- Pastikan data keuangan & AI sudah tercantum seperti di privacy.html
  (data dikirim ke Anthropic untuk fitur AI, disimpan di Firebase/Cloudflare).
