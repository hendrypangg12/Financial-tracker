03 · Data Flow

Data Flow & Sequence

Bagaimana data mengalir antar komponen — 3 skenario utama

🛒 Skenario 1: User Transaksi di POS

[1] User klik "Bayar" di app PWA ↓ [2] saveSale() — write ke localStorage (instant, offline-safe) ↓ [3] Update state.products[].stok (decrement) ↓ [4] showStruk() — render thermal print preview ↓ [5] DEBOUNCED 30s: cloudSync.push() — POST ke Cloudflare Worker ↓ [6] Worker validates api_key + tenant_id ↓ [7] Worker writes ke Cloudflare KV (snapshot per tenant) ↓ [8] PARALLEL: Firebase Firestore sync (per-user document) ↓ [9] Auto-sync ✓ — data tersedia di multi-device + AI bot

🤖 Skenario 2: Owner Tanya AI Bot Telegram

[1] Owner kirim chat "Stok beras berapa?" ke @BerstockBot ↓ [2] Telegram → Webhook ke berstock-bot.workers.dev/webhook ↓ [3] Worker validasi X-Telegram-Bot-Api-Secret-Token ↓ [4] Lookup tenant via chat_id mapping (KV) ↓ [5] Build context: snapshot terbaru dari KV + system prompt ↓ [6] Call Anthropic API (claude-sonnet-4-6) dengan tools=[12 tools] ↓ [7] Claude memilih tool: get_product_info({nama: "beras"}) ↓ [8] Worker eksekusi tool — query KV snapshot ↓ [9] Hasil tool dikirim balik ke Claude ↓ [10] Claude format response Bahasa Indonesia natural ↓ [11] Worker → Telegram sendMessage API ↓ [12] Owner terima reply (~5 detik total)

🎯 Skenario 3: Lead Capture dari Web

[1] Visitor isi form lead di chat widget berstock.id ↓ [2] Submit → POST berstock-bot.workers.dev/api/lead ↓ [3] Worker validate input (nama, wa required) ↓ [4] PARALLEL EXECUTION: ├── [4a] Send Telegram notif ke ADMIN_TELEGRAM_CHAT_ID │ (alert real-time ke owner Berstock) ├── [4b] Save lead ke KV dengan TTL 90 hari ├── [4c] GA4 trackEvent('lead_captured') └── [4d] User redirect ke wa.me dengan context pre-filled ↓ [5] Owner Berstock terima ping Telegram < 5 detik ↓ [6] Owner buka WA, chat lead langsung dengan context
⚡ Performance Karakteristik
• Frontend load: ~200ms (CDN cached)
• POS transaction save: instant (localStorage), 30s debounce ke cloud
• AI bot reply: 4-7 detik (tergantung kompleksitas tool use)
• Lead notif → Telegram: <5 detik

Multi-layer security architecture sesuai best practice 2026

🛡️ Access Control

Per-User Isolation
Firestore Security Rules: user hanya bisa akses dokumen di path users/{uid}/... milik mereka.
Tenant Isolation (Bot)
Setiap tenant punya unique api_key + tenant_id. Cross-tenant query diblokir di Worker level.
Admin Whitelist
Hardcoded list di auth.js: 3 email allowed. CollectionGroup query untuk admin panel.
DDoS Protection
Cloudflare Layer 7 — auto-mitigate attack tanpa konfigurasi. Free tier sudah include.

📦 Data Privacy Commitment

🇮🇩 Data Sovereignty
• Data toko user disimpan di Firebase Firestore (region: asia-southeast1 — Singapore)
• Data bot (snapshots) di Cloudflare KV (region: distributed edge)
• Data tidak dijual ke pihak ketiga
• Data tidak dipakai untuk training AI generic (Anthropic enterprise terms)
• User export data dengan 1-klik (.json) — full data portability

06 · White-Label & Self-Hosting

White-Label & Self-Hosting

Bisakah orang lain pakai sistem ini sendiri? — penjelasan honest

❓ Pertanyaan: "Bisa di-share ke orang lain biar mereka customize sistem sendiri?"

🎯 Jawaban Singkat
Bisa, dengan 3 model: (1) White-Label, (2) Self-Hosted, (3) Source Code License. Masing-masing punya trade-off berbeda.

📦 Model 1: White-Label (Multi-Tenant Hosted)

AspectDetail
Apa yang dapet klienSub-domain custom (misal: klien1.berstock.id) + branding sendiri
Yang di-host diInfrastruktur Berstock (kami yang manage)
Customization yang bisaLogo, warna, nama produk, system prompt AI bot, fitur flag on/off
Customization yang TIDAK bisaDatabase schema, core business logic, integrasi pihak ketiga arbitrary
Pricing modelSetup fee + monthly/yearly + revenue share
Tech requirement klienTidak perlu — klien tinggal pakai

🏠 Model 2: Self-Hosted (Klien Manage Sendiri)

AspectDetail
Apa yang dapet klienSource code lengkap + dokumentasi + 1x setup assistance
Yang di-host diInfrastruktur klien sendiri (Cloudflare account klien, Firebase project klien, dll)
CustomizationFULL control — klien bisa ubah apa saja di kode
Cost klien (infra)~Rp 0-100rb/bulan (sama free tier seperti kami)
Cost klien (Anthropic API)Variable (klien bayar langsung ke Anthropic)
Tech requirement klienDeveloper paham JS, Cloudflare Workers, Firebase. Bukan untuk non-technical.
Pricing modelOne-time license fee + optional yearly support
Update / fitur baruKlien pull dari repo Berstock (jika subscribe support) atau develop sendiri

📜 Model 3: Source Code License (Enterprise)

AspectDetail
Apa yang dapet klienSource code + perpetual license + opsional rebrand total
Yang di-host diInfrastruktur klien (private cloud, on-prem, cloud provider pilihan)
CustomizationUNLIMITED — klien bisa fork, rebrand, modifikasi total
RestrictionTidak boleh re-distribute sebagai product baru kecuali ada perjanjian khusus
PricingCustom (mulai Rp 50jt+, tergantung scope)
Cocok untukKorporasi besar, government agency, SaaS B2B yang mau punya stack sendiri
⚖️ Honest Recommendation
Untuk UMKM: Pilih hosted Berstock (Rp 500rb/bln) — tidak perlu manage infra.
Untuk software house: White-label (Model 1) — bisa rebrand untuk klien sendiri.
Untuk korporasi besar: Source code license (Model 3) — full control + private.
Untuk dev individu yang penasaran: Self-host (Model 2) — bayar setup, dapat code.
